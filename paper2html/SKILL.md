# Skill: 论文 × 源码 · 对账解读页（paper2html）

把「一篇论文 + 一个开源代码仓库」变成一页**主张 × 实况**的对照解读网页：论文的主张逐条落到逐字源码；代码按一次机制真实发生的顺序解剖；覆盖机制保证逐行讲解；交互上带阅读层次与毛玻璃放大镜。

## 何时使用

- 用户给出论文（arXiv 链接 / PDF / 标题）+ 官方代码仓库，要求「解读 / 讲透 / 做成网页 / 深读」
- 用户想把「论文说的事」和「代码做的事」对照核验（传播稿事实核查、传播版本 vs 原文）
- 素材含演示视频（X/推文视频、YouTube、mp4 直链），希望作为佐证媒体嵌进页面
- 关键词：paper walkthrough、code walkthrough、源码详解、对账、解读网页、annotated code、论文+代码打通

## 何时不用

- 只要论文解读、不涉及代码（可沿用本技能的视觉系统与质量红线，跳过代码部分）
- 只要代码浏览（直接用源码浏览器思路或 IDE）
- 纯新闻聚合长文

## 输入与前提

1. 论文原文可抓取（arXiv HTML 版最优：`arxiv.org/html/<id>vN`；否则 PDF 转文本）
2. 代码仓库可克隆/下载（需要完整文本源码）
3. 可运行 Python（高亮与生成）+ 打开浏览器验证

## 流水线（8 步）

1. **核实事实层**：arXiv 元数据（标题/作者/机构/版本/收录）+ 仓库元数据（tree、license、commit、stars、包名）。传播稿数字先对原文。**媒体素材采集**：X/推文视频用 fxtwitter API 取 mp4 直链与封面——`Invoke-RestMethod https://api.fxtwitter.com/<user>/status/<id>` → `tweet.media.videos[].url` / `thumbnail_url`；YouTube 用 oEmbed 取标题与封面。记录发布者与发布时间。
2. **抓论文骨架**：章节 → 主张清单。每个主张给：一句解读 + 逐字英文引文 + 中文直译 + §出处。**引文必须逐字**，不许转述冒充。主张解读按「讲清楚」结构写（见下节）。
3. **抓代码骨架**：tree API 拿全量文件清单与体量；grep 类名/def/关键常量，定位机制对应的文件、类、函数。
4. **锚点摘录**：按内容锚点（子串）截取代码段，行号即真实行号。**禁止手抄代码**——一律从克隆源读取，防止编造。
5. **行区间注解**：每个代码块拆成若干注解区间（区间以内容锚点声明；重名函数/类用 `occ` 指定第几次出现）。注解内容＝「这行干什么 + 为什么 + 论文对应」。
6. **覆盖核对（铁律）**：非空非结构行必须落在某条注解区间；空行/纯标点行自动豁免。构建时逐行核对，漏行直接报错并附行号，改到 100% 为止。此机制会抓出锚点错位、重名类抓错实例等真实 bug。
7. **结构组装**：序（问题：反差句 + 一句话心智模型）→ 若干「主张 → 代码×注解 → 核对结论」单元 → 证据链 → 开源生态与时间线 → 边界（显眼成段）→ 传播版本校验 → 尾声核对一览 + 记住三行（首行复现心智模型）。
8. **视觉与交互**：公文纸白/墨黑/朱红 tokens；码×解互文配对；图型不重复；阅读层次（速读/精读/全量）；玻璃放大镜（hover 平滑聚焦、毛玻璃卡、点击钉住、Esc 复位）；顶部进度条；盖印章。

## 表达方法（「讲清楚」结构，参考 Akshay Pachaar 讲解体）

解读与主张段的写法，按这套结构走，不堆术语：

1. **开场反差句（破预期）**：先否定最常见的误读，再给真结论。范式：「关键差异不是 A，是 B。」
2. **一句话心智模型**：整篇的可记忆锚点，正反对仗式对比，如「开放答案空间 → 生成；封闭答案空间 → 评估」。放在「序」，尾声「记住三行」里复现。
3. **一个具体场景走一遍**：不讲抽象定义，讲「假设有个 agent 在处理一次失败的部署，它要判断 a/b/c/d 四件事……」——读者先看到东西在动，再回来看机制。
4. **原语枚举，每条一句话说人话**：组件/原语逐个列，格式＝名字 + 一句平实解释 + 一个例子。
5. **数字带行动含义**：数字不裸奔，必须接处置（91% vs 9% → 自动路由；52% vs 48% → 升级人工）。与「数字给减法依据」红线互补：一个管可核算，一个管可行动。
6. **边界声明要显眼**：「它不擅长什么」单独成段，不藏脚注。与本技能的「边界」单元呼应。
7. **防过度宣称**：类型安全防的是「格式错误」不是「判断错误」这类 nuance 必须写出，不许让读者得出比原文更强的结论。
8. 短句陈述优先；一个句号一个意思。

## 覆盖机制（本技能与「讲个大概」的分界线）

- 注解＝行区间（锚点声明），不是「挑几句讲讲」。
- 生成器打印 `coverage: n/n lines`；<100% 构建直接失败。
- 每块代码标题显示「注解 n/n 行」，读者可自查。
- 覆盖行左缘淡朱线；注解编号自动（①②③…），注解卡带精确行号（L976–979）。

## 交互系统

- **阅读层次**：速读（主张+图+结论，论文式流）／精读（默认，+代码注解）／全量（+核对台账）。按钮全部可见、当前态高亮；localStorage 记忆选择。
- **毛玻璃放大镜（iOS 质感）**：悬停代码行或注解 → 该注解区间被 `backdrop-filter` 玻璃卡（圆角 14px、半透明白、内高光、柔影）托起并放大到 15.5px；其余行缩至 11px、压暗、0.6px 虚化（失焦景深）；卡片随区间切换平滑位移；点击钉住；Esc/点空白复位；代码横向滚动时玻璃卡跟随重定位；注解栏同步玻璃卡。固定行高 22px，放大不跳动。
- **章节侧栏**：>1480px 显示竖排章节条，滚动跟随高亮。
- 尊重 `prefers-reduced-motion`（自动关过渡与虚化）。

### 铁律

- **朱红只做三件事**：印章、功能性标记（节号/引文线/进度条/行区间徽标/图注编号）、active 态。主版面不做渐变、不用圆角、不加阴影（交互层的毛玻璃卡片按「交互系统」执行，是唯一例外）。
- **线的分层**：3px+1px 双线=信头/权威；1px 实线=结构分隔；dotted=次级；dashed=补位/待核对。
- **框的体系**：视口卷宗外框（fixed inset 12px/16px 双层）→ 内容框（.fig/.codebox）→ 框中框（内衬细线）→ 印章（旋转 -4° 方框）。
- **字号纪律**：中文正文 16px / 行高 1.95；英文引文 italic 15.5px；mono 标注 10–11px + letter-spacing；代码 12.5px、行高固定 22px（放大不跳动）。

### 版式骨架（按序）

1. topbar（sticky）：档案号 ｜ 阅读层次按钮 ｜ 章节导航
2. letterhead：双线信头 → 特大标题（引号朱红）→ 斜体英文副题 → meta 四字段（发布方/日期/性质/体例）→ 右上印章（500ms 盖印动画，仅一次，全站仅一枚；编号 `DOC. 机构缩写-YYYYMMDD`）
3. stat-band：4 格大数字（tabular-nums，可含一个反讽数字位）
4. toc：编号目录 + 交互提示（识别而非记忆）
5. part-divider：罗马数字空心描边（-webkit-text-stroke）+ 朱红短横 + 一句说明
6. duet（对读）：grid `1fr 1px 1fr`，左原文/中缝/右旁注；hover 时节号与 gutter 变朱红
7. prose：单栏 max-width 860–900px
8. colophon：框中框「立场与局限」+ 来源 footer

### 摘引体例

- **引文块**：左 2px 朱红 border + paper-deep 底；外文原文 italic + 中文直译加粗 + mono 出处标注。仅用于关键句。
- **忠实转述**：普通段落，力求贴近原意，不做概念性改写。
- **旁注**：注一/注二…，一条只说一个论点（修辞动作 / 证据等级 / 未言之处 / 可自行核算的反证数字）。

### 图表系统（8 型，选型速断）

| 图型 | 做法 | 适用 |
|---|---|---|
| 比例条 | CSS 条形 | 数量/百分比对比 |
| 点阵 | CSS grid 方格 ×N | 大数具象（如门控开合率） |
| 论证链 | flex 节点框 + 箭头 | 消融/证据等级递减 |
| 热力矩阵 | 表格 + 朱红透明度分档 | 多主体 × 多维度 |
| 链路图 | SVG 节点网 | 系统结构/信息流 |
| 阶梯图 | SVG 折线阶梯 | 多方案对比（如 GSM8K 四种流程） |
| 堆叠条 | CSS flex 分段条 | 时间账/预算拆解 |
| 条带图 | CSS 单元格序列 | 路由/位置语义 |

- class 约定：`.ln`（细线）`.lnd`（朱红虚线）`.bx`（实线框）`.bxs`（浅框）`.nd`（节点圆）`.tx/.txb/.txr`（标注文字）
- 统一格式：细线框 + `FIG. NN` 朱红编号 caption + fig-note 释文；**同页图型不重复**；全部手写 HTML/SVG/CSS。

### 媒体卡（VID. NN，佐证视频）

- 结构：`<figure class="vid">` → `<video controls preload="none" poster="封面图" src="mp4 直链">` → `<figcaption>`：`VID. NN` 朱红编号 + 标题 + 发布者/日期 + 原文链接。
- 视觉沿用图表系统：细线框、无阴影无圆角；caption 样式同 FIG。
- 断网降级：`preload="none"` 保证离线打开不卡；断网时只剩 poster + 标题 + 原链，仍可读。
- 可选完全离线：用户要求时把 mp4 下载到 `<页面名>.assets/` 改相对引用；此时产出变多文件，交付时说明。
- 视频是本页唯一允许的外链（见质量红线）。

### 响应式与无障碍底线

- <960px 单栏堆叠；`prefers-reduced-motion` 全关动效与虚化；`:focus-visible` 朱红 outline；交互控件带 `aria-pressed`。

## 质量红线

- 引文逐字 + 出处；解读与原文分层（引文块 vs 解读段），旁注不冒充论文立场。
- 代码逐字摘自克隆源，行号可回查；禁止手写或改写后冒充。
- 数字必须能给出减法依据（如 24.18 = 44.88 − 20.70），权重/门控等机制数字指出对应行。
- 传播稿逐条核对：说法 vs 原文 vs 判定（属实/大体属实/基本属实/夸大/观点）。
- 单文件离线 HTML；系统字体栈（Georgia/SimSun/Consolas/微软雅黑）；无外链（**唯一例外：佐证视频**，须 preload=none + poster + 原链降级，并在媒体卡注明来源与日期）。
- 产出文件放 `Documents\notes\`（不写桌面）；生成后 `Start-Process` 打开。

## 迁移到新论文的改造点

1. 换 CLAIM_* 引文（逐字，带 § 出处）与主张解读段（按「讲清楚」结构：反差句 → 心智模型 → 具体场景 → 原语枚举）。
2. 换代码锚点（文件路径、起始子串；重名时加 `occ`）。
3. 写注解区间（每块先粗后细，跑生成器看 UNCOVERED 报错，补区间至 100%）。
4. 换 8 张图里的数据（SVG 可先从上一版复用再改数字）。
5. 跑 `python scripts/gen_recon.py` → 看 `coverage: n/n` → `Start-Process` 验证（放大镜、三种阅读层次、印章、目录锚点）。
